# Keeping Attribute Growth Stable

Status: Design proposal. Updated: 2026-11-27. Requirements: R-01, R-04, R-05, R-06, D-21, D-22.

[Design index](README.md) · [Barracks attributes](52-barracks-attributes-and-raid-stats.md) · Previous: [Calculating raid stats and damage](53-calculating-raid-stats-and-damage.md) · [Run growth](06-run-growth-roguelite.md) · [Threat Tiers](07-meta-progression-and-difficulty.md) · [Class resource loops](28-class-resource-loops.md)

**A veteran should feel the first useful find of a raid.** If the operator already shrugs off the ambush, opens the cabinet before a patrol can arrive and has a spender ready after every shot, a better drop table won't make searching interesting again. Keep three comparisons separate: what training changed with the same kit, what swapping one piece changed with the same training, and what the run find changed with both held still. Doc 06's `M × G × R` is useful for comparing those layers across a raid. It isn't an instruction to multiply every hit by meta level, Gear Rating and raid level.

## Three ways growth can go wrong

| Failure | What gives it away | Proposed correction |
| --- | --- | --- |
| An advanced attribute does too much | One point buys a stronger hit, a shorter interval **and** a refund from each extra hit. Even different-looking builds all want the same point. | Budget the whole group of benefits. Pair a modest combat change with a field use, as in [52](52-barracks-attributes-and-raid-stats.md). Give later investment smaller direct gains (for example, resolve an aptitude's points with doc 18's stat formula `e × n / (1 + 0.1 (n − 1))`, which stays below `10 e` however many points are assigned); let later class levels mainly open variant choices. Leave gear enhancement on its own piece. Don't multiply the results by class level or shared Rank after conversion. |
| A secondary stat never changes a decision | A player offered load handling always takes damage because no valuable return trip is actually slowed by cargo. A resource-gain roll at an already full bank is similarly empty. | Compare the loaded walk to extraction with the empty outward trip; ask whether the stat changes which find is worth carrying. If neither route nor exposure changes, drop or replace that line. Don't make every class slow, every search longer or every enemy tougher just to sell it. |
| Modest-looking bonuses multiply without limit | Damage per round, rate of fire and a trigger on each hit each look reasonable alone. In a pack, extra hits buy more copies and refunds until the player never needs to aim another builder. | Pool like bonuses under [53](53-calculating-raid-stats-and-damage.md). Rate and damage really do multiply in damage per second, so compare the combination over a whole encounter. Restrict refunds to their named spend, give duplicate stacks smaller marginal returns, and prevent a copy or splash from restarting its own chain. |

Watch **time and probability** as closely as damage. Repeated cuts to a cooldown can nearly erase the gap between actions. For repeatable cooldown bonuses, this proposal supersedes the per-stack timer multiplication in [18, section 5](18-demo-classes-elites-and-items.md): express the benefit as recovery rate, add like bonuses and convert to seconds once. This is a change of unit, not a reuse of the old percentages. In either case, preserve the time a player needs to aim, commit and recover. Combine critical chance in percentage points within its natural probability range. If the next line would buy no more eligible critical hits, don't offer it as a meaningful upgrade. Evaluate resistance by *hits survived*: taking the remaining small fraction of a blow and halving it again can double survival time. Check that against barrier recovery and healing in the same fight before adding another resistance source. None of these decisions needs a new numerical ceiling, but keep the existing ones in the new units: damage reduction stops at 75% in `Raid.recalc`; gear cooldown reduction stops at 50% in `compileSkills`, a recovery-rate sum of +100%; and a repeated item resolves through doc 18's stat formula before it joins the rate sum. Without that last step a pile of Coolant Loops would still shrink the gap toward zero; with it, Piercing Line's 2.5 s can fall no lower than about `2.5 / (1 + 1 + 0.64) ≈ 0.95 s`.

**The Charge warning is already visible.** John reports too much time at full Charge in [28](28-class-resource-loops.md). `Raid.updatePlayer`, `gainCharge` and `castSpender` in `src/sim/raid.js` explain why more gain can be a poor reward: recovery continues while searching, builders add to it, and a ready bank cannot spend through an active cooldown. Full-bank bonuses in [24](24-skill-resource-and-synergies.md) can reward staying there. Keep doc 28's first experiment: ease routine builder gain and watch whether the next spend becomes a decision. Measure wasted gain alongside occasions when a player *could* set up and use the signature. Merely emptying the bar is no success if Blade never gets its opening or the Handler never gets a rupture in a short fight.

## What would change the proposal?

These are comparisons to run later, not balance results. Start at the same Threat Tier on the same route, with the same ordinary rooms and a lone elite. Increasing tier at the same time as training would hide which change mattered.

- **Fresh versus veteran, same kit and no finds.** Try each native kit without a rare item or a tree requirement. Look for the Rifleman's aimed pack discharge, Blade's opening against a living enemy, a Summoner order that the sentry can answer, and a Handler rupture before the room is empty. Then swap one variant: a discharge along a corridor should win there and give something up at a crowded doorway. If it wins both purely on damage, revise the branch under [39](39-class-levels-and-barracks-variants.md).
- **Ordinary versus unusually strong finds.** Hold training and gear fixed and add one find, then several copies, to each run. Compare shots and time to clear the same front plate from either angle, signature uses per actual setup, seconds exposed while searching, and whether the operator can bring the same cargo home. Inspect the strongest combination as well as the typical one. If a frontal burst never breaks through, revisit the plate; if aim and facing stop mattering after one duplicate, revisit the stack before raising enemy health.
- **Return to base and redeploy.** Compare extraction with death, accounting separately for class XP and kept gear. With the same training and equipped pieces the next starting sheet must match the previous starting sheet, even after a run with exceptional stacks. Only then change a Barracks allocation or equip a processed find and compare again. Repeat at a higher chosen tier to check the risk and reward trade of [07](07-meta-progression-and-difficulty.md); don't silently scale the same street to cancel the operator's growth.
