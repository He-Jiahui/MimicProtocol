# Equipment and Loot: What a Drop Is Worth

Status: Draft v0.1. Updated: 2026-11-26. Requirements: R-01, R-12, D-06, D-20, D-22.

[Back to index](README.md) | Previous: [25 Combat Feel](25-combat-feel-reference-brushwild.md) | Next: [27 Skill Tree](27-skill-tree-reference-brushwild.md)

**Proposal:** Keep the four-slot operator kit. Improve the decision *after* extraction: when two pieces have the same Gear Rating, the Lab and Armory should tell the player which part of their build would change. Brushwild supplies a useful way to answer that question, but no reason to remove the uncertainty of carrying a Tainted item home.

**What the designs promise beyond the code.** [08](08-loot-contamination-and-legendary-gear.md) describes extracting and installing powers; its demo override removes those operations. [23](23-demo-boss-loot-and-drops.md) instead assigns a fixed, non-transferable Latent Power with a drawback to a Legendary. [24](24-skill-resource-and-synergies.md) adds the slot Aspect at Rare and above. These are separate rewards. `bossKilled` in `src/sim/boss.js` actually drops `2 + tier` pieces for the Matron; `rollGear` tries `0.06 × tier rare multiplier` **per boss piece**. The first-kill Core bonus is real; doc 23's per-kill Signature roll, guaranteed first Legendary, pity counter and 70% weapon-family match are not implemented. A Prototype Boss Cache choice is a raid item, not stash equipment.

## 2. Proposal: make the swap legible first

After Process, compare the *same class and other three pieces* before and after a hypothetical swap. Use `gearStats` for affix totals and `compileSkills` (`src/sim/skill-build.js`) for resolved intervals, Charge capacity and Overdrive duration. Use a hub baseline with no run items or temporary buffs; say so. Show changed rows with units, then list rules gained and lost. Do not convert conditional rules into a single damage score. Show the same detail on selection as on hover so touch users can inspect it. Before Process, retain the signal view; sort order, highlights and deltas must not reveal affixes, Prime or power identity.

For example, compare otherwise identical Rare rigs, one Overclocked and one Primed, with no other bonuses. Rating and base skill damage tie. Equipping Primed changes capacity **100 → 120**, Overdrive **8 → 6 s**, and the start condition to **begins with full Charge**. The choice is between opening a raid ready to spend and sustaining a longer burst later. Neither rig deserves an unconditional green upgrade arrow.

## 3. Proposal: keep powerful loot worth extracting

- **Legendary identity.** Pilot one doc 23 signature from the Matron pool, attached to the item at drop and revealed only by Process. Hollow Heart is a useful design test: [08](08-loot-contamination-and-legendary-gear.md) specifies a chance for M1 kills to detonate the body **and make noise**. Show both on one line beside, not instead of, the weapon Aspect. The existing `compileSkills` deals in a limited set of effects; an M1-only kill, noisy blast and exclusion of its own secondary kills need source-aware runtime behavior. Do not register it as an unrestricted `kill` trigger. Defer new Uniques, sockets and extraction of Powers. Settle whether a pity counter tracks a kill or a banked reward before attaching it to profile progression.
- **Class weighting.** If a Summoner gets too many irrelevant lines, pilot a soft weight on one boss affix draw (e.g., double `summon` for Summoner or `dot` for Toxic). Keep all eligible lines, the four slot odds, rarity odds, Aspect rules and item count unchanged. Record baseline and trial shares by class, slot and rarity; inspect useful off-class pieces too, since the stash survives class changes. This adapts the purpose of doc 23's weapon-family bias; it does not claim to implement that rule. Add affix groups or item-level gates only for documented conflicts, using the same eligibility on rerolls.
- **Hub economy and stash.** Keep sale for Cash, Process for Samples and enhancement for long-term investment. Prefer slot/identification filters over more tabs; retrieve a saved off-class rig without needing to equip it. Defer a mystery shop: guaranteed hub supply would compete with risking another raid. If stash records show a surplus of unsold gear, trial dismantling *identified, unequipped, non-training* gear for Samples **instead of** Cash. Measure the net Sample cost after Process; a process/dismantle loop should not print Samples. Never salvage unprocessed goods as a shortcut around contamination.

## 4. Proposal: preserve item rolls without rewriting old gear

Brushwild stores `{id, roll}` per affix, plus an optional skill target, and stores a roll for the power. `affixValue`, `aspectValue` and `itemEffects` resolve those at read time. DarkSignal's `affixRange` scales the bounds with item level; `rollAffix` saves `{k, v}` rounded to a tenth. Its Prime flag applies to the item. There is a concrete tuning discrepancy: normal `f` is drawn in `[0.7, 1]` then remapped over the *entire* affix interval. Prime draws `f` in `[0.9, 1]`, which after the same remap covers the upper **third**, not the upper tenth specified by [23](23-demo-boss-loot-and-drops.md). An item-level Prime tag is not evidence of a 90th-percentile line.

For new gear, store the normalized position in the final interval, the affix ID and a roll-table version. Roll once at drop; Process reveals, reroll replaces only the selected line, enhancement continues to change the base. If doc 23 wins, draw Prime positions directly in `[0.9, 1]` for new drops. Decide separately whether rerolling a Prime item must retain that floor: today's `rerollAffix` passes `prime = false`. Keep named Aspects and fixed Latent Powers as IDs; do not introduce random strength where the design specifies none.

`loadProfile` currently rejects versions other than `PROFILE_VERSION` (1). Read v1 explicitly before any version increase. Preserve a legacy line's exact saved value and label its percentile unknown: rounding discarded information. Keep UID, enhancement, hidden state and sale value on load, including on equipped items and in the stash. Resolve new rolls against their saved table version; retroactive rebalancing should be a separate decision. Preview and combat must read the same resolver.
